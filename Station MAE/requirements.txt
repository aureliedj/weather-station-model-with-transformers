# The +cu128 build of torch is NOT published on PyPI — it exists only on
# PyTorch's own index. Declaring that index HERE means a plain
#     pip install -r requirements.txt
# works on Renku. Previously this needed an --extra-index-url flag on the
# command line, and forgetting it produced the misleading error
#     ERROR: Could not find a version that satisfies torch==2.13.0+cu128
#            (from versions: 2.5.0, … 2.13.0)
# — that version list is PyPI's, which never contains local "+cuXXX" tags.
--extra-index-url https://download.pytorch.org/whl/cu128

# Core deep learning
# Linux (Renku): the CUDA 12.8 build.
#   History: this pin exists because an EARLIER Renku node had a driver that
#   topped out below 12.8, so the default PyPI wheel (cu130) failed CUDA init
#   and fell back to CPU silently.
#   As of 2026-07-31 the node reports driver 580.159.04 / CUDA 13.0, which is
#   NEWER than 12.8. Drivers are backward compatible, so cu128 still works, and
#   the pin is kept because it is known-good. If you ever want to simplify, the
#   default PyPI wheel should now also work on this driver — verify with
#   scripts/verify_env.py before trusting it, and only change it between runs,
#   never mid-experiment.
# macOS (local): plain build (MPS/CPU; no CUDA-variant wheels exist).
# After installing, run scripts/verify_env.py — a silent CPU fallback looks
# exactly like a working install until a 3-day training run finishes.
torch==2.13.0+cu128; sys_platform == "linux"
torch==2.13.0;       sys_platform == "darwin"
